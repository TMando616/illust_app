# イラスト変換アプリ（Swift）仕様書 v1

Nov 21, 2026 · @まんどぅ

## 概要と決定事項

アルバムの写真を、若い人向けのシンプルなイラスト風に端末内で変換するiOSアプリ。画風のお手本は妻が描くオリジナルの絵で、他のアプリにはない絵柄が強みになる。

| 項目 | 決定内容 |
| --- | --- |
| 言語・UI | Swift / SwiftUI（無音カメラと同じ） |
| 入力 | アルバムから選ぶだけ。アプリ内撮影はなし |
| 画風 | シンプルなイラスト系（若い人向け） |
| お手本 | 妻が描く。着手は後でよい |
| 処理 | 端末内（Core Image ＋ Core ML）、サーバーなし |
| 収益化 | 全画面広告 ＋ リワード広告（バナーはなし） |
| 無音カメラとの関係 | 別アプリ。将来合算できるように作る |

## 変換方式

形を単純にするのはCore Imageのフィルター、絵柄らしさを加えるのはCreate MLのスタイル転送、と役割を分ける。

**なぜ組み合わせるか**

- スタイル転送は「色と筆の質感」を写す仕組み。写真の細かい影や質感は残るので、単体では「シンプルなイラスト」にはならない。
- 形の単純化（平らな色面＋輪郭線）は、画像処理の組み合わせで安定して出せる。
- 写真をアニメ風にする公開モデル（AnimeGANなど）は、商用利用できないライセンスが多い。自前で学習するにはイラストが数百枚単位で必要になるため、見送る。

**処理の流れ**

1. **縮小**：長辺1024〜2048pxに縮める。小さいほど細部が消えてイラストらしくなり、処理も速い。
2. **平滑化**：輪郭を残したまま色をならす。標準フィルターで足りなければMetalで自作のカーネルを書く。
3. **色数を減らす**：6〜10色程度にまとめる。妻の絵から取ったパレットに色を寄せると、絵柄の統一感が出る。
4. **線画を重ねる**：輪郭を抽出して線の太さと色を整え、上に重ねる。
5. **スタイル転送**：妻の絵で学習したモデルで質感を加える。元画像との混ぜ具合を強さとして調整する。

お手本が届くまでは1〜4だけでも完成品として成り立つ。モデルは後からファイルを差し替えるだけで追加できる。

## 画面構成と操作の流れ

「選ぶ → 画風を選ぶ → 保存」の3タップで終わるようにし、2画面だけで構成する。

1. **ホーム**：「写真を選ぶ」ボタンと、画風のサンプル（変換前後の例）。ボタンで`PhotosPicker`を開く。これは写真へのアクセス許可が要らない。
2. **編集画面**：
   - 上：変換後の画像。長押しで元の写真を表示
   - 中：画風のサムネイルを横並び。タップで切り替え
   - 下：「線の太さ」「強さ」のスライダー
   - 最下部：「保存」と「広告を見て高画質で保存」の2つのボタン
3. **保存後**：「保存しました」と共有ボタン（シェアシート）を出す。通常保存の場合は、ここで全画面広告を挙む

編集画面では、プレビューを小さい解像度ですぐに表示し、保存時だけ本番の解像度で変換する。切り替えを待たせないため。

## 広告設計

保存ボタンを「通常保存（全画面広告あり）」と「高画質保存（動画広告を見る）」の2つに分け、どちらでも広告が1回入る作りにする。リワード広告は本人が自分で選んで見るので不満が出にくく、単価も高い。

| 広告 | 出すタイミング | ルール |
| --- | --- | --- |
| 全画面（インタースティシャル） | 通常保存が完了した後 | 2回に1回、かつ前回から3分以上空ける。初回の保存では出さない |
| リワード | 高画質保存ボタンを押したとき | 最後まで見たら保存。広告を読み込めないときはそのまま保存させる |

- **なぜ保存後か**：操作の区切りに出すのはAdMobの推奨で、編集中に割り込ませるとポリシー違反や低評価の原因になる。
- **なぜ初回は出さないか**：使い始めに広告が出ると、そのまま削除されやすい。
- 広告は前もって読み込んでおき、押してから待たせない。
- トラッキング許可（ATT）、テスト広告ID、プライバシーの申告は無音カメラと同じ手順。

## お手本画像とモデル作成の手順

1つの画風につき、妻に描いてもらうのは「お手本の絵1〜3枚」と「使う色の一覧」だけ。着手は後でよく、それまでは仮の絵で開発を進める。

**妻にお願いするもの（画風1種ごと）**

- 平らな色とはっきりした線の、いつもの画風の絵を1〜3枚。人・食べ物・風景など、アプリでよく変換されそうなものが入っていると理想
- その画風で使う色の一覧（6〜10色）。色数を減らす処理のパレットになる
- 縦横1000px以上の画像データ（紙なら明るい場所で真上から撮影）
- アプリでの利用と、アプリ内でのクレジット表記について一度言葉で確認しておく

**Create MLでのモデル作成**

1. Create MLで「スタイル転送」のテンプレートを開く
2. お手本の絵を「スタイル」に、変換対象になりそうな写真数十枚を「コンテンツ」に入れる
3. 学習し、画面上のプレビューで結果を確認。スタイルの強さを変えて数パターン作る
4. 書き出した`.mlmodel`をXcodeのプロジェクトに入れる

仮のお手本には、自分で描いた簡単な絵か、著作権が切れた絵を使う。ネット上のイラストは公開版には入れない。

## 実装ステップ（Claude Code用）

最初に「変換結果がイラストに見えるか」だけを試作で確かめ、見た目に納得してからアプリを作る。ここがこのアプリの一番の不確定要素だから。

1. **試作**：Mac上のSwift（Playgroundかコマンドライン）で処理の流れ1〜4を組み、手元の写真10枚で変換結果を並べて見る。パラメータはここで詰める。
2. **プロジェクト作成**：SwiftUIアプリと、変換処理を入れるSwift Package（`IllustrationKit`）を作る。
3. **写真選択と表示**：PhotosPickerで選んだ画像を編集画面に表示。写真の向き情報の補正もここで。
4. **変換の組み込み**：試作の処理を`IllustrationKit`に移し、画風切り替えとスライダーをつなぐ。プレビューは小さい解像度で。
5. **保存と共有**：本番解像度で変換して保存、透かしの有無、シェアシート。
6. **スタイル転送**：仮のお手本で作ったモデルを組み込み、元画像との混ぜ具合を強さスライダーにつなぐ。
7. **広告**：AdMobの全画面・リワード広告をテストIDで、出す頻度のルールも実装。
8. **お手本の差し替えと公開**：妻の絵でモデルとパレットを作り直し、アイコン・スクリーンショットを用意して審査に出す。

シミュレーターでも動くが、変換の速さは実機で確認する。目安は保存時の変換が2秒以内。

## 無音カメラとの将来の合算に備えること

変換処理をアプリ本体から切り離し、`IllustrationKit`というSwift Packageにまとめておく。合算するときは、無音カメラがこのパッケージを読み込むだけで済む。

- **入出力を`CIImage`に統一する**：無音カメラのフィルターもCore Imageなので、撮影フレームをそのまま渡せる。
- **画風を「データ」として持つ**：名前・パレット・モデルファイル・初期値を1つの定義にまとめ、コードを変えずに画風を足せるようにする。
- **広告の処理も共通化しておく**：頻度のルールやATTの処理を両アプリで使い回せるように。
- 撮影中のリアルタイム変換は処理が重い。合算するときは「撮影は色味フィルターだけ、撮影後にイラスト化」が現実的。
